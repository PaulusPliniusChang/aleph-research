# 探索度与策略采样（精简）

> 当前设计附录；正文见 `docs/requirements/00-requirements-discussion.md` 第 6 节。

## 1. 机制

探索度是派发策略的动作层参数，不传给模型采样接口。策略谱系为 L0 精修、L1 增量、L2 重构、L3 探索：

| 策略 | 分支起点 | 改动幅度 | 行为约束 |
| --- | --- | --- | --- |
| L0 | 当前 SOTA | 极小 | 最小必要修改 |
| L1 | 当前 SOTA | 中等 | 单一模块增量 |
| L2 | 当前 SOTA | 较大 | 模块替换或重组 |
| L3 | 稳定基线 | 极大 | 从问题出发提出新方向 |

派发时按探索度对策略做 Boltzmann 采样：

```text
P(strategy_i) = exp(Q_i / tau) / sum_j exp(Q_j / tau)
```

温度只控制分布的集中程度，不直接选择层级；层级是采样结果。对外暴露 exploration 标量，内部按目标分布校准 tau。

## 2. Q 估计

Q 表示单位成本的期望增益，由成功概率、增益幅度、执行成本与步数组成。使用 Beta 先验与时间衰减，按战役更新；每个策略设置采样下限，避免采样集中在既有高估值策略。

## 3. 约束校验

提交时由运行时检查改动行数、文件范围、允许与禁止路径、依赖锁与测试结果。违规任务不进入晋级流程，记录结果并保留原分支。

## 4. 调度

采用探索优先：起始 exploration 取 0.7；按已消耗预算分阶段；连续多轮没有 SOTA 提升时重升温并限制次数；预算接近上限时强制利用。策略成本画像进入队列与回填，预算不足时拒绝高成本策略。

## 5. 记录与复现

每次采样记录随机种子、exploration、Q 向量、概率、策略、分支基线与 prompt 哈希，存入 SQLite；支持离线重放采样。人工覆盖动作记录在任务事件中。
