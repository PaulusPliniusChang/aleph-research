# 最优结果缺少人工选择和回退操作

## 当前修复验收（2026-10-31）

修复代码已推送至派生仓库分支 `fix/aleph-11-safe-best-selection`，产品提交为 `eb386d8f6a9b2d35deb36fb22c7cfac8d9a6cdc2`，上游基线为 `785a7e9ce6420f62c5187662a3e8ba7b6d5977bf`。本次修改只包含 Host、插件说明、架构说明和选择操作测试。修复仅处理原 #12 中已证实的已检出分支一致性残留，当前选择仍指向记录中的最优结果，没有新增任意历史结果选择需求。

Host 在需要移动目标时枚举实际 Git 工作树，发现主目录或关联目录已经检出该分支，就在更新引用前拒绝，并给出准确目录及保存、提交后切换分支的说明。路径按 NUL 分隔读取，能够保留中文、空格和换行。枚举失败时拒绝更新；未检出的目标继续比较更新。目标已经等于最优提交时直接成功，不要求清理未提交文件。显式非分支引用不能被用作选择目标。产品不会隐式重置、暂存或清理研究文件。

## 最新架构正式复核（2026-10-31）

当前上游基线为 `785a7e9ce6420f62c5187662a3e8ba7b6d5977bf`。维护者已经通过 `3cb4b48` 增加 `/api/aleph/select-best`，并关闭原 #12；原来的“完全缺少入口”描述不再代表当前实现。该接口可以把目标研究分支指向 `best.commit`。当前没有注册同名模型工具，正式检查使用实际 HTTP 接口，不把工具目录缺少名称当作接口不存在。

当前仍有选择结果与后续代码起点不一致的残留：Host 对目标分支执行 `git update-ref`，即使该分支已经在主研究目录或关联工作树中检出，也只修改分支引用，不处理或拒绝索引与工作文件不一致的情况。

例如，算法 `10` 已完成评估并成为最优结果，之后研究目录提交了算法 `20`。调用默认选择接口后，接口返回成功，主分支的 `HEAD` 已指向算法 `10`，工作文件和索引却仍包含算法 `20`。原本干净的目录变成已暂存修改，直接运行算法仍会执行 `20`。如果目录原来还包含暂存、未提交和未跟踪修改，选择也会成功移动 `HEAD`。当前证据没有发现文件丢失；问题是成功响应不能保证分支历史和实际继续研究的代码一致。

B 在本次发布前重新依次获取上游与派生仓库，并对干净主分支执行仅快进同步；本地及上游仍为上述基线。

[实际 DSH 启动脚本](dsh/current-select-best.py)使用隔离 Host、真实会话、注册项目与评估工具、持久存储、Git 关联工作树、真实 Python 评分，以及经过认证的选择接口。脚本没有调用模型、修改产品源码或缩短期限。[实际记录](evidence/11-current-real-dsh-select-best.json)中的 95 项观察全部符合缺陷与对照预期，[原始输出](evidence/11-current-real-dsh-select-best.txt)包含完整运行结果。这些观察通过表示缺陷成功复现，不表示产品通过修复验收。

## 问题

系统只在出现更高分时自动更新最优结果，缺少选择历史实验、回退最优分支或指定历史结果继续研究的正式操作，Leader 无法据此调整研究方向。

## 复现

1. 在 DSH 中完成并保存不同分数的历史实验。
2. 查看实际 Aleph 会话的工具及参数。
3. 检查是否支持选择历史结果、回退或从指定历史提交继续研究。

## 实际结果

历史实验已经存在，但正式工具没有相应操作或参数。

## 预期结果

可以选择已有实验作为最优结果，或回退至指定结果，后续任务从所选代码开始。分支、分数和起点记录保持一致；无效选择应被拒绝，其他实验记录仍保留。

## 验证

DSH `0.2.2-alpha.2` 隔离环境中已有 10 分和 20 分的实验，真实工具目录确认缺少相应入口。证据见 [工具目录](evidence/09-11-real-dsh-tools.json) 和 [历史实验](evidence/04-real-dsh-sota-race.json)，被测版本与自动测试见 [验证记录](VALIDATION-2026-10-31.md)。结论限于 Aleph 正式工具；自动晋级的并发问题由 [ALEPH-04](04-sota-promotion-race.md) 处理。
